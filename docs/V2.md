## 1. Product flow (Vercel-style)

1. Landing page → **Sign in with GitHub** (the App's own OAuth).
2. Empty dashboard → **Connect GitHub** → GitHub App install page (All repos or Selected repos).
3. Redirect back with `installation_id` → **Import** screen listing the installation's repos, with an Enable toggle per repo.
4. Enabled repo → webhook reviews its PRs. No workflow file, no secrets on the user's side.
5. New repo detection:
   - `installation_repositories` webhook (repo added to the install).
   - `repository` created event (when the user chose "All repos").
   - Sift stores the repo as `pending` and shows a "N new repos, import?" banner. Optional email or Telegram ping.

## 2. Architecture changes

| Piece | Plan |
|---|---|
| Auth | GitHub-only login (Auth.js, Better Auth, or hand-rolled OAuth code flow). No email/password. Other providers later. |
| Tenancy | `Installation` table, `Repo.installationId`, `User` ↔ `Installation`. **Every dashboard query scoped to the user's installations.** Highest-risk change: today the dashboard is global behind a passcode. |
| Webhook | `POST /api/github/webhook`: HMAC verify, idempotent on `X-GitHub-Delivery`, 202 fast. |
| Runner | `runPrReview` via the T-28 seam (`readFile` over the contents API). Start with Next `after()` + high `maxDuration`; move to Vercel Queues or a worker if flaky. |
| Tokens | App JWT → short-lived installation token per job, in memory only. |
| Cost | Sift pays for model calls unless BYOK (see §4). |

**Known limitation in App mode:** no git checkout on Vercel, so impact analysis (T-16) and stack/patch-id (T-15) are off. Core review, grounding, rank, dedupe and risk labels work. Later fix: fetch the repo tarball into `/tmp`, or run a worker with git (Fly/Render).

## 3. Dashboard redesign

Data already exists (`Review`, `Finding` with placement and outcome).

- **Overview:** PRs reviewed, findings by severity, accept rate, median wait for human approval, "needs attention" list (high-risk PRs).
- **Activity feed:** timeline of Sift's comments, newest first. Each item: repo + PR, severity badge, quoted code, comment text, **View on GitHub** link. Filters: severity, category, outcome. Verify `Finding` stores the GitHub comment URL/id; if not, small additive migration.
- **PR detail:** diff-style view, findings anchored to lines, inline vs summary-only, Accept / Ignore buttons feeding the T-20 feedback loop.
- **Repo settings:** enabled toggle, feature flags (impact, stack, feedback), minimum severity, ignored paths.
- **Re-run review** button.

## 4. Cheap value-adds

- **Opt-in per repo by default.** Setting "auto-review new repos", default off, so connecting 40 repos doesn't burn the model budget.
- **BYOK.** User pastes their own Gemini/OpenRouter key per workspace, encrypted at rest. Fixes cost and rate limits.
- **Budget guard.** Daily model-call cap per installation; visible "paused: budget reached" state.
- **Privacy.** Findings store `quotedCode` from private repos: add a retention setting and a delete-my-data control.
- **Coexistence (T-35).** App installed + Action present → Action exits 0, one review per push.
- **Keep the paste page** as the zero-login demo path.
